## 概念速通：对象、桶、键和两个默认设置

对象存储和你在用的云服务器硬盘不是一回事。对象由文件数据和它的元数据组成；桶是顶层命名空间容器；键是对象在桶内的唯一标识。整个结构是扁平的，没有真正的文件夹层级，`2026/11/photo.jpg` 只是一个带斜杠的键名，不是目录。这也是它容量能一直堆上去、不用担心分区写满的原因。

按 AWS 官方文档的口径，S3 体系的桶名要求全局唯一且小写，不同账户之间不能重名；桶和对象默认私有；桶级别的 Block Public Access 默认开启，官方建议除非确有需要，否则保持开启；ACL 默认被禁用，授权应走桶策略、访问点策略或 IAM 策略。这套默认值对做图床的人有直接影响：想让图片被公网读到，正确做法是用桶策略放开读权限，而不是去开 ACL。

一致性方面，AWS 官方说明所有区域对对象的 PUT 和 DELETE 都提供强读后写一致性，覆盖新建、覆盖写和删除，对象标签、元数据这类读取同样强一致。也就是说文件写完立刻就能读到“刚写进去的那一版”，不需要等几分钟。这一点比耐久性数字更容易被忽略，但恰恰决定了你的程序要不要写重试和延时逻辑。

关于可靠性，AWS 公开的设计口径是 11 个 9 的数据耐久性（99.999999999%）和默认 99.99% 可用性。这是 S3 这套体系普遍被引用的背景值，不是雨云的承诺，雨云的对象存储没有公开对应指标，别把这两个数字当成你买到的 SLA。

AWS 这几年还把桶拆出了专用类型：面向高并发的目录桶（默认每账户 100 个，默认禁止公共访问且不可更改）、面向 Apache Iceberg 表格数据的表桶、面向向量检索的向量桶。普通用户接触不到，知道有这回事就够了。

## 冷热分层：为什么大厂要分存储类别，雨云分了没有

对象存储的成本逻辑建立在“数据会变冷”上。AWS 把存储类别铺得很细：S3 Standard 放频繁访问的热数据，Standard-IA 和 One Zone-IA 放低频访问，Glacier Instant Retrieval、Glacier Flexible Retrieval、Glacier Deep Archive 三档归档层层降低单价，S3 Intelligent-Tiering 则在四个访问层之间自动迁移数据，官方称这项功能已为客户省下超过 60 亿美元存储成本。数据越冷，单价越低，取回越慢越贵。

雨云这套套餐没有按访问频率分层的存储类型。你选的档位决定的是“能装多少”和“能取多少”，不决定数据冷不冷。对大多数个人和小团队来说这反而是好事：不用判断数据温度，也不用担心生命周期规则配错把热数据沉到归档里。但它有一个明确的代价——**一年都不动一次的冷数据，在套餐制里和天天读的热数据一个价**。真有大量长期归档需求，按量计费的归档型存储更合适，下面会算给你看。

## 兼容与迁移：手上那些 S3 工具能不能直接用

雨云对象存储兼容 S3 协议，rclone、s3cmd、Cyberduck 这类工具可以直接连上去操作，不用换一套接口。这也意味着迁出成本很低：真要走，用 rclone 做一次 sync 就能把桶里的东西拉到本地或另一个 S3 兼容的存储上，不存在“数据搬不走”的锁定。

一个实例由一个 AccessKey 统一管理所有存储桶，权限按桶级别配置。单人用没问题，多人协作或者要给不同项目做隔离，就得分实例。

同区域的云服务器和对象存储之间走内网地址互传，上行下行都不计流量。如果你已经在雨云开了宁波或十堰的机器，把对象存储开在同一区域，回源这部分成本直接归零。

需要提前确认的是 AWS SDK 的对接细节。第三方工具能连，不代表你代码里那套 SDK 的所有特性都支持，尤其是分片上传的并发参数和签名版本。拿一个测试桶先跑通上传、下载、列举、删除四个动作，再往生产迁移。

## 三个容易踩的坑

**流量超了不会自动扣费，而是停止访问。** 这是雨云和纯按量计费最大的行为差异：套餐额度用尽后，默认直接停掉访问，不会悄悄给你记账。省心归省心，但图床突然 403 比账单涨几十块更难受。希望超出后继续可用，要去控制台手动开启弹性计费。

**年付 7 折锁的是周期。** 折扣是真的，但一次性付清一年之后，中途想升档、降档或者不用了，规则和按量计费不一样。用量还没摸清的阶段，先用月付跑一个月，看看控制台里的实际存储量和流量曲线，再上年付。

**10 元那档不是给图床准备的。** 流量优先 10GB + 50GB 只有 10GB 存储，装几百张压缩后的图片就见底了。它适合小程序图片、API 静态资源这种文件少但被频繁拉取的场景。

## 什么情况下不该选雨云

只说几 GB 文档备份的个人用户，最低 10 元/月也不算贵，但如果你要的只是同步几份表格和照片，网盘或者大厂免费额度更省事，没必要为这个开一个对象存储实例。

已经深度使用某一家大厂生态的团队要谨慎。权限模型、CDN 回源、数据湖查询工具都长在那套 IAM 和桶策略上，为了省流量费换一家，跨云取数的流量成本和改造工时很可能把省下的钱吃回去。

纯冷归档的场景前面算过了，2TB 归档在按量计费的归档层下大约 61 元/月，套餐制在这个场景没有优势。归档型存储取回一般另外计费，也有最短存储期，这一点下单前自己核一下。

## FAQ

**雨云对象存储兼容 S3 API 吗？**
兼容。rclone、s3cmd、Cyberduck 可以直接对接，支持自定义域名、防盗链和防火墙规则。用 AWS SDK 的话建议先拿测试桶验证签名和分片上传。

**按量计费还是包月？**
套餐按月扣费，长付年付约 7 折。超出套餐后默认停止访问，需要在控制台手动开启弹性计费才会转为按量。

**流量怎么算？**
套餐额度用于抵扣对外提供访问产生的流量。把文件传上去、以及同区域云服务器走内网读写，不占这个额度。超出后宁波按 0.1 元/GB、十堰按 0.2 元/GB 计。

**能不能做公网图床？**
可以。支持绑定自定义域名和配置防盗链，配合桶级别的访问权限设置对外读。

**以后想迁走麻烦吗？**
不麻烦。S3 兼容意味着用 rclone 或者任意 S3 客户端都能整体同步出去，迁出过程产生的流量按出方向计费。

**能退款吗？**
雨云的云服务器和游戏云支持 7 天内无理由退款，每个账号限 3 次，日付和试用产品不适用。对象存储是否适用同一政策，公开资料里没有写清楚，下单前问一句比较稳。
